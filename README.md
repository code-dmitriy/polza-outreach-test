# Тестовое задание Polza Agency — вайбкодер-аутричер

Скрипты для сбора базы B2B-компаний, проверки её качества и генерации
персонализации для холодного аутрича.

## Запуск

```bash
pip install -r requirements.txt
python -m src.cli --help
```

Python 3.11+. Ключи и токены не обязательны: всё, кроме сбора через hh.ru,
работает без них.

```bash
cp .env.example .env    # и заполнить, если нужен hh.ru или Anthropic
```

## Команды

| Команда | Что делает |
|---------|-----------|
| `python -m src.cli audit` | Задача 4: ищет в базе строки, где название, почта и сайт относятся к разным компаниям |
| `python -m src.cli enrich` | Задачи 2 и 4: собирает факты с сайтов и заполняет колонку «Персонализация» |
| `python -m src.cli emails --preview` | Задача 3: собирает цепочку писем, проверяет лимит в 120 слов |
| `python -m src.cli hh-check` | Проверяет, что токен hh.ru подхватился |

Результаты складываются в `out/`: CSV для импорта в Google Таблицы и
Markdown-отчёты для чтения глазами.

## Как это устроено

```
src/
  audit.py        проверка чужой базы на перепутанные строки
  site_facts.py   обход сайта компании: почты, имена ЛПР, факты с цифрами
  personalize.py  колонка «Персонализация», провайдер переключается флагом
  emailcheck.py   синтаксис, ролевые ящики, публичная и одноразовая почта, MX
  sequence.py     цепочка писем из data/task3_sequence.json
  textnorm.py     сопоставление названия компании с доменом, включая транслит
  http_client.py  вежливый клиент с файловым кешем
  sources/hh.py   источник компаний — API hh.ru
```

### Решения, которые стоит объяснить

**Сначала аудит, потом персонализация.** Персонализировать строку, в которой
сайт принадлежит другой компании, нельзя: факт будет взят с чужого сайта и
уйдёт чужому адресату. Такое письмо выдаёт себя с первой строки и жжёт домен
сильнее, чем отсутствие персонализации. Поэтому `enrich` обогащает только
строки со статусом `ok`, а по остальным пишет в комментарии, что именно не так.

**Решает живой сайт, а не эвристика.** Похожесть домена на название — только
повод присмотреться. Окончательный ответ даёт заход на сам сайт и поиск там
названия компании. Обратная сторона: если сайт целиком на иероглифах, сверить
нечем — такая строка помечается «проверить вручную», а не «перепутано».
Ровно этот случай есть в базе задачи 4: `mgwmachine.com` выглядит чужим для
Mingwen Intelligent, но принадлежит именно ей.

**Персонализация не выдумывается.** У каждого факта хранится адрес страницы,
с которой он взят, и он едет в таблицу отдельной колонкой — проверяющий может
открыть ссылку и увидеть тот же текст. Провайдер `extractive` (по умолчанию)
берёт формулировки с сайта и не обращается ни к какой модели. Провайдер
`anthropic` получает те же вытащенные куски и только переписывает их живым
языком: придумывать ему нечего. Если отдать модели одно название компании,
она начнёт сочинять «ваш опыт на рынке с 2009 года», и такая персонализация
хуже, чем никакой.

**Фильтр качества на выходе.** Текст, который формально вытащился, но
состоит из китайского меню или перечня ключевиков через запятую, в письмо не
попадает: такая «персонализация» сразу выдаёт скрипт. Лучше пустая ячейка и
пометка «использовать нейтральный вариант».

**SMTP-верификации нет сознательно.** На холодной базе это лишний повод для
жалобы, а на catch-all доменах она всё равно врёт. Проверяем то, что даёт
честный ответ: синтаксис, тип ящика, живость домена по MX.

**Кеш ответов в `.cache/`** — не ради скорости, а ради воспроизводимости:
прогон через неделю на лежащем сайте должен дать тот же результат.

## Тесты

```bash
python -m pytest -q
```

Сетевых вызовов в тестах нет: аудит проверяется в режиме `verify_online=False`,
иначе набор падал бы каждый раз, когда у чужой компании лежит сайт.

## Известные ограничения

- API hh.ru с 2025 года отвечает `403` без токена зарегистрированного
  приложения. Токен генерируется один раз на https://dev.hh.ru/admin и кладётся
  в `.env` как `HH_TOKEN`.
- `extractive` отдаёт формулировки с сайта как есть — местами это сырой текст.
  Перед отправкой такие строки стоит просмотреть глазами.
- Имя ЛПР берётся только там, где компания сама публикует его рядом с
  должностью. Сведением профилей из разных источников скрипт не занимается.
